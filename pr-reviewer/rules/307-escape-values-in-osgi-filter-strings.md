# 307: Escape Values in OSGi Filter Strings

When an OSGi filter string concatenates a value that is neither a code constant nor a number, escape the value with `SystemBundleUtil.escapeFilterValue(value)`. This covers every filter passed to `ConfigurationAdmin.listConfigurations`, `createFilter`, `getServiceReferences`, or a service tracker, and every reference target, whenever the value comes from a request, a REST path, an external reference code, a file name, stored data, or text entered by a user or an administrator. A search filter sent to an LDAP directory server, such as one passed to `LdapContext.search`, is not an OSGi filter and has its own escaping, so this rule does not apply to it.

**Rationale:** The filter syntax (section 3.2.7 of the OSGi Core specification) treats `\`, `*`, `(`, and `)` inside a value as syntax. An unescaped `*` turns an equality match into a presence or substring match, a `(` or `)` either fails the parse with an `InvalidSyntaxException` or adds clauses of its own, and a `\` silently escapes the character after it. Looking up a configuration by the external reference code `com.liferay.Foo~*` matched every instance of the factory, and a value of `x)(companyId=2` added a clause that matched the configuration of another company. Escaping makes a value match only itself. A wildcard that the code writes on purpose, such as a `*` default that matches any value, stays unescaped. So do code constants, such as `Foo.class.getName()`, and numbers, such as a company ID, since neither can contain these characters.

A violation is a filter string that concatenates a value that is neither a code constant nor a number without passing it through `SystemBundleUtil.escapeFilterValue`, including a value that is escaped by hand.
