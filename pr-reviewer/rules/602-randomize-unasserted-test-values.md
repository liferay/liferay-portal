# 602: Randomize Test Values You Do Not Assert

Examine every hardcoded string and number in a test. If no assertion checks its value, replace it with `RandomTestUtil` (`randomString`, `randomLong`, and so on). This covers URLs, file names, IDs, names, exception messages, and JSON field values passed into setup, construction, a mock, or a builder — anything the test only passes through and never asserts on. Keep a hardcoded literal only for a value the test actually checks or that the implementation requires — for example, the only enum value an endpoint accepts, or a field whose absence would cause the call to fail. When such a value appears more than once, write the literal at every use. Give a value a constant only when the constant holds a generated value, which the test cannot spell out twice, or links a fixture input to an assertion, such as a URL handed to a mock and then checked with `startsWith`. Never hoist an asserted literal into a constant whose name only restates it, such as `_PAGE_SIZE_STRING = "5"`.

**Rationale:** A hardcoded literal signals that the exact value matters. When it does not, the literal misleads the reader into looking for a significance that is not there. A random value proves the test does not depend on it and surfaces any accidental coupling to a specific input.

A violation is any hardcoded string or number in a test that no assertion depends on and that the implementation does not require, where `RandomTestUtil` should be used. Before flagging a hardcoded non-asserted value, verify with `git grep --cached` against the implementation that the value is not required. Examples: a URL or file name passed to a mock or a builder, an exception message in `new SomeException("Some error")`, a folder name in `addFolder("Test Folder")`, a portal URL the test never checks, or a JSON `"message"` value when the test only asserts a flag such as `isQuotaExceeded()`. The related violation is hoisting an asserted literal into a `private static final` constant whose name only restates it, instead of writing the literal at each use, even when it repeats. Do not flag a repeated asserted literal written inline, and do not flag a constant that holds a `RandomTestUtil` value or that links a fixture input to an assertion.

**Example:** commit `5df4f1a` replaced `"Test Folder"` with `RandomTestUtil.randomString()`; `1b0e932` replaced fixed file names with `randomString()`; `8dcff7c` promoted reused random values to named constants so the input and the assertion share them; liferay-portal-ee commit `9b80e67` inlined `_NESTED_FIELDS`, `_PAGE_SIZE_STRING`, and `_PAGE_STRING` back into both expected maps, while keeping `_SEARCH` (a `RandomTestUtil` value) and `_HOME_PAGE_URL` (handed to a mock and asserted with `startsWith`).
